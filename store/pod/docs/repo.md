# Docs: in the repository

- **Acceptance criteria and short specs:** on the work item itself.
- **UX specs and design notes that outlive the work item:** a markdown file under the project's docs folder, added in the same change request as the code, or in its own change request when it comes first.
- **Decisions:** a short dated record beside the design notes: context, decision, consequences.
- **Lessons:** the pod's lessons file under the host's pod folder, changed only by `em` through a change request.
- Keep documents short and link them from the work item. A document nobody links is lost.
