# Super mode - optional milestone recipe

Load this only after Forge classifies the request as delivery and the user selects super mode or an explicit whole-app milestone build-out. It extends the Forge agent's canonical Steps 1-7; all shared permissions, progress/recovery, quality gates, and model inheritance still apply. Super mode is an orchestration choice, not a host model setting.

1. **Size the work.** If one cohesive ship task is enough, say `Mode: ship - no milestone backlog needed` and use the normal loop. Do not manufacture milestones.
2. **Pre-flight.** Require a clean working tree before branch/commit work. Preserve existing changes; ask before stashing or altering them. Create a dedicated local branch/worktree, never commit to `main`/`master`, and ask before `git init` when needed. Record the branch in the task packet. Explicit no-commit or no-write constraints override this recipe.
3. **Plan first.** Ask `architect` for app-level design and an ordered milestone backlog. Surface it using the host checklist, or plain text if unavailable, before implementation. Persist only when allowed. Each milestone has its own acceptance checklist and current status.
4. **Build each milestone.** Apply the same contract -> decomposition -> implement -> green gate -> review -> refine loop. Include relevant documentation with the code. Retain the framework build and existing regression suite when those gates exist. Escalate high-risk security, performance, domain, and accessibility work using the normal SME rules.
5. **Commit approved work only.** A milestone is done only when its contract is met, the green gate passes, and the independent reviewer returns `APPROVED`. With commits allowed, auto-commit that milestone to the dedicated local branch, record its evidence when audit writes are allowed, mark it complete, and continue. Never push or force-push automatically. Missing review, self-review, or failed gates do not authorize an auto-commit.
6. **Bound refinement.** Keep the normal per-milestone review-cycle bound and require open blocker/major findings to decrease. If a milestone stalls, stop and report partial progress and residual findings rather than repeating it. Healthy long work is not a failure because of its duration or tool count.
7. **Interrupt and resume.** On interruption, honor the user's latest effects restrictions before any checkpoint write. Use the shared Resume packet with backlog status, completed artifacts, evidence, and the next action. Save only where authorized; do not create a WIP commit automatically. On resume, revalidate state and permissions and skip already completed milestones.
8. **Concurrency and degradation.** Prefer top-level Forge. Use foundation-first work for shared contracts, then independent, file-disjoint partitions in separate worktrees and one coherence review. If nesting prevents delegation, announce that review is self-performed, not independent, and run serially. Report the reduced assurance; do not turn self-review into automatic commit authority.
9. **Finish.** Stop when the app contract is satisfied or the user interrupts. Include milestone counts, branch, verification, review kind, audit persistence status, and residual risks in the normal Forge result. No automatic publication.
